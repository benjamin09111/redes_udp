# eBird como capa de metadatos de ocurrencia aviar para el simulador UAV

## 1. Qué aporta eBird, qué no demuestra y qué productos/endpoints son pertinentes

### Takeaway
eBird es una fuente comunitaria de **observaciones registradas**, lugares de observación y productos modelados de ocurrencia/abundancia relativa; sirve para contextualizar dónde y cuándo se han reportado aves, no para localizar aves en vuelo ni para estimar por sí sola un riesgo de colisión en tiempo real. En este proyecto las aves **no son una amenaza modelada**, no bloquean nodos/aristas y no modifican el costo de ruteo: la capa sólo apoya la revisión humana previa a la misión.

### Cited Findings
- La API pública está diseñada para salidas limitadas, recientes y resumidas; cada consulta requiere una clave personal única solicitada desde la página de descarga de datos. — [eBird Help: Download eBird Data](https://support.ebird.org/en/support/solutions/articles/48000838205-download-ebird-data)
- La documentación de API v2 describe las observaciones recientes como registros de hasta 30 días y devuelve sólo la observación más reciente; por ello “reciente” no equivale a telemetría ni a una posición actual. — [eBird API 2.0](https://documenter.getpostman.com/view/664302/S1ENwy59)
- Los endpoints útiles para una vista local son `GET https://api.ebird.org/v2/ref/hotspot/geo?lat={lat}&lng={lng}&dist={km}` (hotspots cercanos), `GET /v2/ref/hotspot/{regionCode}` (hotspots de región), `GET /v2/data/obs/geo/recent?lat={lat}&lng={lng}&dist={km}&back={days}` (observaciones cercanas recientes) y `GET /v2/data/obs/{regionCode}/recent` (recientes por región); la referencia de la API confirma parámetros espaciales para hotspots y observaciones cercanas. — [eBird API v2](https://documenter.getpostman.com/view/664302/S1ENwy59); [referencia de endpoints](https://hackage.haskell.org/package/ebird-api/docs/Data-EBird-API.html)
- Un hotspot es un lugar de observación compartido: eBird ofrece listas de hotspots con coordenadas mediante su API, y sus páginas muestran estadísticas y frecuencia semanal de observaciones. No es un polígono de ocupación aérea ni una medición de aves presentes. — [FAQ de hotspots](https://support.ebird.org/en/support/solutions/articles/48001009443-ebird-hotspot-faqs); [ejemplo de página de hotspot](https://ebird.org/hotspot/L2309145)
- El eBird Basic Dataset (EBD) contiene una fila por observación de especie en una lista, además de esfuerzo, latitud/longitud y otros metadatos; es el producto para análisis histórico con contexto de muestreo, no la API de resultados recientes. — [eBird Help: Download eBird Data](https://support.ebird.org/en/support/solutions/articles/48000838205-download-ebird-data)
- Los productos eBird Status and Trends estiman rangos estacionales, abundancia relativa estacional/semanal y tendencias mediante modelos que combinan observaciones eBird y covariables ambientales; son estimaciones de población/ocurrencia relativa, no detección de individuos. — [Términos de Status and Trends](https://ebird.org/about/products-access-terms-of-use); [FAQ de eBird](https://ebird.org/about/faq)
- Los registros de especies sensibles se oscurecen en salidas públicas y el acceso requiere una solicitud que describa el proyecto y uso; por tanto, la ausencia en esta capa tampoco demuestra ausencia de fauna. — [eBird Help: Download eBird Data](https://support.ebird.org/en/support/solutions/articles/48000838205-download-ebird-data); [política de especies sensibles](https://support.ebird.org/en/support/solutions/articles/48000803210-sensitive-species-in-ebird)
- Para el área de estudio sí existen listas públicas en Quintero, incluso una lista pelágica con aves marinas; esto confirma presencia de registros históricos públicos, no presencia actual ni altura de vuelo en una ruta concreta. — [lista eBird Quintero, 2018](https://ebird.org/checklist/S46047085); [lista eBird Quintero--Pelágico, 2025](https://ebird.org/checklist/S211167770)

### Inferences
- La etiqueta correcta es **“Contexto de ocurrencia aviar (eBird)”** o **“Registros comunitarios de aves (eBird; no detección en tiempo real)”**. Evitar “amenaza aviar”, “radar de aves”, “riesgo de colisión” y “zonas de exclusión de aves”, porque los productos citados no proporcionan posiciones, trayectoria, altitud, velocidad, tamaño de bandada ni probabilidad de impacto. — [API eBird](https://documenter.getpostman.com/view/664302/S1ENwy59); [Status and Trends](https://ebird.org/about/products-access-terms-of-use)
- El backend puede conservar la clave y transformar resultados API en una respuesta temporal para la interfaz; no debe incrustar la clave en JavaScript público ni compartirla. Esto es una consecuencia operativa de que la clave está vinculada a la cuenta y el titular debe protegerla/no compartirla. — [Términos de API](https://www.birds.cornell.edu/home/ebird-api-terms-of-use/)
- El modelo de ruteo debe ignorar deliberadamente esta capa: ningún `exceeds`, bloqueo, costo de arista, invalidez automática de muestra ni decisión LPP/GPP puede originarse sólo en eBird. Esa es una decisión de alcance del simulador y evita convertir datos observacionales no operacionales en una falsa señal dinámica.

### Gaps
- No se encontró una fuente eBird que proporcione para Quintero/Puchuncaví posiciones de aves en tiempo real, altitud de vuelo, vectores de movimiento, tamaño de bandada o una probabilidad validada de colisión UAV; no debe inferirse ninguno de esos atributos de la API.
- La documentación pública no fija un umbral universal de distancia, densidad o antigüedad que transforme un registro eBird en una prohibición de vuelo; tales umbrales no deben inventarse.

## 2. Diseño de visualización y tratamiento temporal/espacial recomendado

### Takeaway
La visualización debe separar explícitamente **lugares históricos de observación**, **reportes recientes con fecha de corte** y, sólo con autorización apropiada, **patrones estacionales modelados**. Para Quintero/Puchuncaví conviene mostrar agregados y metadatos de cobertura, no pines que parezcan objetivos o aves vivas.

### Cited Findings
- eBird presenta en los hotspots frecuencia semanal de observaciones y permite cambiar el período mostrado; estas frecuencias describen la actividad de reporte en el sitio. — [ejemplo de hotspot eBird](https://ebird.org/hotspot/L2309145)
- Status and Trends produce estimaciones a escala continental del ciclo anual y sus productos incluyen ocurrencia, abundancia relativa y tendencias; los datos espaciales pueden descargarse para GIS como GeoTIFF y GeoPackage tras el proceso de acceso. — [FAQ eBird](https://ebird.org/about/faq); [descarga de datos eBird](https://support.ebird.org/en/support/solutions/articles/48000838205-download-ebird-data)
- El EOD anual contiene especie, fecha y ubicación, pero no los metadatos de esfuerzo; el EBD sí conserva detalles de esfuerzo y muestreo. — [eBird Help: Download eBird Data](https://support.ebird.org/en/support/solutions/articles/48000838205-download-ebird-data)
- Las rutas GPS de eBird Mobile no son públicas ni se comparten con terceros; no son un insumo disponible para reconstruir trayectorias de aves o de observadores. — [privacidad y uso de datos eBird](https://support.ebird.org/en/support/solutions/articles/48001078113-ebird-data-privacy-and-data-use)

### Inferences
- Implementar tres subcapas opcionales, independientes del grafo: **Hotspots eBird** (puntos/cluster, persistentes); **reportes eBird recientes** (celdas hexagonales o cuadrícula, no marcadores de individuos); y **patrón estacional de ocurrencia relativa** (raster/contornos sólo si Cornell autoriza ese uso). Cada leyenda debe indicar fuente, fecha de consulta, ventana temporal, número de listas/observaciones si está disponible, y el aviso “no es detección ni predicción de aves en tiempo real”. — [API eBird](https://documenter.getpostman.com/view/664302/S1ENwy59); [Status and Trends](https://ebird.org/about/products-access-terms-of-use)
- Para los reportes recientes, agrupar por celda y período (por ejemplo, 7/14/30 días seleccionable), representar recuentos de listas/especies reportadas y conservar el último `obsDt` visible en un panel. El color debe significar “intensidad de reportes en la ventana”, nunca “riesgo”. La API limita estas salidas a observaciones recientes/resumidas y no equivale a presencia actual. — [eBird Help: Download eBird Data](https://support.ebird.org/en/support/solutions/articles/48000838205-download-ebird-data); [API eBird](https://documenter.getpostman.com/view/664302/S1ENwy59)
- Para planificación estacional humana, preferir una vista por semana/mes y especie o gremio que explicite **“abundancia relativa estimada”** y año/versión del producto; no sumar especies ni reinterpretar el raster como densidad aérea o probabilidad de choque. — [Términos de Status and Trends](https://ebird.org/about/products-access-terms-of-use)
- La interfaz debe permitir ocultar por defecto la capa y mantenerla fuera de las capas de `amenazas`. Una leyenda/tooltip debe incluir: “Los reportes pueden estar sesgados por esfuerzo de observación; ausencia de reporte no equivale a ausencia de aves.” El soporte de esta precaución es que sólo EBD aporta esfuerzo y que especies sensibles/registros no públicos pueden faltar de resultados públicos. — [eBird Help: Download eBird Data](https://support.ebird.org/en/support/solutions/articles/48000838205-download-ebird-data); [revisión/calidad eBird](https://support.ebird.org/en/support/solutions/articles/48000795278-the-ebird-review-process)
- El resultado adecuado ante mucha actividad histórica/reciente es un estado de **“revisión humana recomendada”**, no “ruta inválida”. Un operador puede comprobar condiciones de campo y adoptar un aplazamiento, desvío manual o aterrizaje seguro si observa aves, especialmente en costa, sitios de descanso o época sensible; dichas medidas son decisiones operacionales externas, no salidas automáticas de eBird.

### Gaps
- No se halló una resolución de celda/hexágono específica validada para Quintero/Puchuncaví por Cornell ni una metodología eBird para convertir conteos API en un índice aeronáutico. Elegir resolución mediante prueba de legibilidad y documentarla como decisión de UI, no como parámetro científico de riesgo.
- Los términos no autorizan asumir que descargar un producto Status and Trends permite servir sus rásteres o derivados en este sitio: la autorización depende del caso de uso y de permiso escrito para plataformas web.

## 3. Licencia, privacidad y contexto aeronáutico: límites de uso operativo

### Takeaway
El uso académico/no comercial puede ser viable con clave, atribución y cumplimiento de términos, pero una capa web debe evitar redistribuir datos crudos y debe solicitar permiso antes de publicar productos Status and Trends. La seguridad aeronáutica reconoce los impactos con fauna como un riesgo, pero sus herramientas de evaluación operacional combinan datos de impactos, radar y modelos; eBird por sí solo no cumple esa función.

### Cited Findings
- Los términos de API conceden una licencia revocable, no transferible y no sublicenciable para uso no comercial —incluidos sitios web, aplicaciones y herramientas de apoyo a decisiones— y requieren permiso escrito previo para cualquier uso comercial. — [Términos de API eBird](https://www.birds.cornell.edu/home/ebird-api-terms-of-use/)
- El usuario debe proteger y no compartir su clave; Cornell puede modificar/descontinuar la API y suspender acceso si el uso afecta sus servidores. — [Términos de API eBird](https://www.birds.cornell.edu/home/ebird-api-terms-of-use/)
- Todo dato mostrado desde la API debe atribuirse a eBird.org y, cuando sea posible, enlazarse a eBird.org. — [Términos de API eBird](https://www.birds.cornell.edu/home/ebird-api-terms-of-use/)
- Los términos de datos prohíben redistribuir/publicar el conjunto original y restringen el uso al propósito solicitado; los derivados que se puedan distribuir deben llevar los mismos términos, además de reconocimiento/citación. — [Términos de acceso a datos eBird](https://www.birds.cornell.edu/home/ebird-data-access-terms-of-use/)
- Para sitios web, plataformas y herramientas de decisión, los términos Status and Trends permiten hasta 250 visualizaciones descargadas sin modificar con atribución, pero prohíben usar los **Data Products** o redistribuirlos/derivados sin consentimiento previo por escrito de Cornell. — [Términos de Status and Trends](https://ebird.org/about/products-access-terms-of-use)
- Si se usa Status and Trends, Cornell exige una cita completa con DOI/enlace y el descargo de responsabilidad especificado; las visualizaciones deben exhibirse tal como se descargaron, incluido logo/cita. — [Términos de Status and Trends](https://ebird.org/about/products-access-terms-of-use)
- La FAA describe AHAS como una herramienta de riesgo para rutas de baja altitud que combina registros de impactos, masa media de aves, radar meteorológico NEXRAD, información histórica y modelos predictivos para estimar actividad actual. — [FAA: recursos sobre fauna](https://www.faa.gov/airports/airport_safety/wildlife/resources)
- ICAO informa que aproximadamente 74% de los impactos con fauna reportados ocurren en o cerca de aeródromos; su análisis de 2016–2021 sitúa 24% durante despegue y 46% durante descenso, aproximación o carrera de aterrizaje. — [ICAO State of Global Aviation Safety 2025](https://www.icao.int/sites/default/files/safety/GASP/GASP%20Library/State%20of%20Global%20Aviation%20Safety/ICAO_SR_2025.pdf)

### Inferences
- Incorporar en el pie de capa: **“Fuente: eBird.org, Cornell Lab of Ornithology. Registros comunitarios agregados; no usar para detección, separación ni decisión automática de vuelo.”** Enlazar a eBird y añadir fecha/hora de consulta. Esto satisface la atribución API y reduce la interpretación operacional errónea. — [Términos de API eBird](https://www.birds.cornell.edu/home/ebird-api-terms-of-use/)
- Antes de desplegar una aplicación pública, comercial, institucional con ingresos o que publique datos/raster precargados, obtener revisión/permiso escrito de Cornell. La opción de menor riesgo es consultar la API desde servidor para visualización no comercial y no guardar/exportar el GeoJSON bruto al repositorio o al navegador como archivo redistribuible. — [Términos de API eBird](https://www.birds.cornell.edu/home/ebird-api-terms-of-use/); [Términos de datos](https://www.birds.cornell.edu/home/ebird-data-access-terms-of-use/); [Términos Status and Trends](https://ebird.org/about/products-access-terms-of-use)
- Una observación de aves puede justificar que el operador declare una muestra de misión **no apta para el objetivo científico** (p. ej., aves visibles que contaminan una medición óptica/acústica) o aplique un procedimiento humano de seguridad; debe quedar registrada como motivo de calidad/operación externo y no como `threat_event`, colisión predicha ni penalización de ruta. Esta distinción es coherente con que la evaluación aeronáutica real requiere múltiples fuentes operacionales, no sólo eBird. — [FAA AHAS](https://www.faa.gov/airports/airport_safety/wildlife/resources)
- Cerca del Aeródromo de Quintero, los procedimientos reales de aeródromo, NOTAM, autoridad aeronáutica chilena y observación in situ prevalecen sobre esta capa histórica. eBird no sustituye autorización, vigilancia visual, ni un sistema certificado de detección/gestión de fauna.

### Gaps
- No se localizó, en esta investigación, una instrucción DGAC Chile específica que convierta datos eBird en restricción de RPAS ni una fuente pública que certifique eBird para evaluación de peligro aviario en Quintero. Consultar directamente a DGAC/administrador del aeródromo y a la autoridad ambiental si el sistema pasará de simulador académico a operación real.
- Las condiciones comerciales/institucionales concretas y el permiso para publicar cualquier derivado Status and Trends deben ser confirmados por Cornell para el caso de uso final; los términos publicados indican contactar a `ebird@cornell.edu`. — [Términos de API eBird](https://www.birds.cornell.edu/home/ebird-api-terms-of-use/); [Términos Status and Trends](https://ebird.org/about/products-access-terms-of-use)
